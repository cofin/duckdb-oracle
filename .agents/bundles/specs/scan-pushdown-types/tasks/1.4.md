# Task 1.4: Implement projection pushdown in OracleInitGlobal, widen 64KB buffers, fix truncation indicators, and harden OracleScanState

## Objective

Remediate findings `H-07` (scan part), `H-08`, `H-09` (scan part), `H-10` (scan part), `H-13` (scan part), `H-16` (scan part), `M-07` (scan part), `M-09`, `M-10`, `M-11` (scan part), and `L-04` in `src/include/oracle_table_function.hpp` and `src/oracle_scan.cpp`:
1. Reorder `OracleScanState` members so `buffers`, `indicators`, and `return_lens` are declared *before* `stmt` (destroying `stmt` *before* its bound buffers), and remove dead `OracleBindData::stmt` and `OracleBindData::conn_handle`.
2. In `OracleBindInternal`:
   - Widen `oci_sizes` to `65535` (`NumericLimits<ub2>::Maximum()`) for `JSON`, `VECTOR`, `SPATIAL`, `XML`, `LOB_CLOB`, `LOB_BLOB`, `LONG_TEXT`, and `LONG_RAW`.
   - Read `OCI_ATTR_CHAR_SIZE` and `OCI_ATTR_DATA_SIZE` into `ub2` variables (`ub2 char_len = 0; ub2 data_size = 0;`).
   - Query `OCI_ATTR_VECTOR_DATA_FORMAT` on `SQLT_VEC` descriptors so `FLOAT64` maps to `LIST(DOUBLE)` and `INT8`/`BINARY` throw `NotImplementedException`.
   - Store per-column converted select expressions (`converted_select_exprs`) on `OracleBindData`. For `oracle_scan`, populate `direct_from_sql` and `direct_select_list_sql` using `converted_select_exprs` even when `needs_wrapper` is true so `WHERE` pushdown stays inside the `FROM` table rather than outside `TO_CHAR(...)`. For `oracle_query` (where `direct_from_sql` is empty), set `pushdown_eligible = false` for `TO_CHAR`-rewritten `DATE`/`TIMESTAMP` columns.
3. In `OracleInitGlobal`:
   - Compute the active scanned column indices from `input.column_ids` and `input.projection_ids` (after `RemoveUnusedColumns` has run).
   - Rebuild the executed SQL query projecting only the active columns (or `SELECT 1 FROM ...` when no columns are projected, e.g. `COUNT(*)`), and allocate OCI `OCIDefineByPos` buffers only for the active columns.
4. In `OracleQueryFunction`:
   - Remove the premature `if (status == OCI_SUCCESS_WITH_INFO) throw ...` before the indicator loop.
   - Check `ind == -2 || ind > 0` for every fetched row/column so truncation is reported with the exact column name even on the final `OCI_NO_DATA` batch.
   - If `status == OCI_SUCCESS_WITH_INFO` and no column indicator triggered, only throw if `OCIErrorCodeMatches(gstate.conn_handle->Get()->errhp, 1406)` (ignoring benign warnings like `ORA-24347`).
5. Validate non-null/non-empty inputs and strip trailing `;`/whitespace in `OracleScanBind` and `OracleQueryBind`; use `bind.settings.call_timeout_ms`; and add optional `as_of_scn` (`UBIGINT`) and `as_of_timestamp` (`VARCHAR`) named parameters to `oracle_scan`.

## Steps

### Step 1: Update `OracleBindData` and `OracleScanState` in `src/include/oracle_table_function.hpp`

- In `OracleBindData`:
  - Remove dead `std::shared_ptr<OCIStmt> stmt;` and `std::shared_ptr<OracleConnectionHandle> conn_handle;`.
  - Add `vector<string> converted_select_exprs;`.
- In `OracleScanState`:
  - Declare `vector<vector<char>> buffers;`, `vector<vector<sb2>> indicators;`, and `vector<vector<ub2>> return_lens;` *before* `std::shared_ptr<OCIStmt> stmt;` so `stmt` is destroyed first.
  - Add `vector<idx_t> active_bind_cols;` and `vector<idx_t> output_to_active_idx;` to map DuckDB output chunk columns to the active OCI define positions.

### Step 2: Update `OracleBindInternal`, `OracleScanBind`, and `OracleQueryBind` in `src/oracle_scan.cpp`

- Use `ResolveOracleConnection` and preserve `resolved.catalog_state` when `state == nullptr`.
- Use `bind.settings.call_timeout_ms` instead of hardcoded `30000`.
- Read `ub2 char_len = 0; ub2 data_size = 0;` via `OCIAttrGet`.
- Query `ub1 vec_format = 0;` (`OCI_ATTR_VECTOR_DATA_FORMAT`) when `dtype == SQLT_VEC`.
- Set `size = 65535` whenever `decision.special_kind != OracleSpecialKind::NONE`.
- Record `bind.converted_select_exprs.push_back(expr)` for each column.
- In `OracleScanBind`: validate non-null/non-empty arguments, support optional `as_of_scn` (`AS OF SCN <n>`) and `as_of_timestamp` (`AS OF TIMESTAMP TO_TIMESTAMP('<ts>', 'YYYY-MM-DD HH24:MI:SS.FF')`), and set `bind->direct_from_sql` so filter pushdown applies directly to the base table.
- In `OracleQueryBind`: validate non-null/non-empty arguments, strip trailing whitespace and `;`, and mark `DATE`/`TIMESTAMP` columns that underwent `TO_CHAR` rewrite as `pushdown_eligible = false`.

### Step 3: Prune projected columns in `OracleInitGlobal` and fix truncation handling in `OracleQueryFunction`

- In `OracleInitGlobal` (`src/oracle_scan.cpp:244-395`):
  - Determine which `column_ids` are actually projected into the output chunk using `input.projection_ids` (or all `input.column_ids` if `input.projection_ids.empty()`).
  - Build the projected `select_list_sql` for only those active `bind_col_idx` columns (using `"1"` if 0 columns are needed for `COUNT(*)`), combine with `bind.direct_from_sql` / `bind.base_query` and `bind.pushdown_clauses`, record `OracleDebugSetLastQuery(query_to_run)`, prepare `gstate->stmt`, and allocate/define buffers only for `active_bind_cols`.
- In `OracleQueryFunction` (`src/oracle_scan.cpp:427-468`):
  - Check `CheckOCIError(OCIAttrGet(gstate.stmt.get(), OCI_HTYPE_STMT, &rows_fetched, 0, OCI_ATTR_ROWS_FETCHED, errhp), errhp, "Failed to get rows fetched")`.
  - Check `ind == -2 || ind > 0` for every row/column in `rows_fetched` before checking `status == OCI_SUCCESS_WITH_INFO`.
  - Only throw on `OCI_SUCCESS_WITH_INFO` when `OCIErrorCodeMatches(errhp, 1406)`.
