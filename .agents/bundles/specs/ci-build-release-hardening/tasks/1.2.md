# Task 1.2: Harden release-unsigned.yml artifact count & smoke test gates, fix integration-tests.yml OCI paths, and upgrade deprecated actions

## Objective

Remediate findings `H-24` (`release-unsigned.yml` and `integration-tests.yml` parts), `M-23` (`release-unsigned.yml` part), and `M-24` across `.github/workflows/release-unsigned.yml`, `.github/workflows/integration-tests.yml`, and `.github/workflows/main-distribution-pipeline.yml`:
1. In `release-unsigned.yml`:
   - In both `deploy-gh-pages` and `create-release`, change `if [ "$ACTUAL_COUNT" -ne "$EXPECTED_COUNT" ]` to `exit 1` instead of printing a warning and publishing an incomplete release.
   - Replace the false-positive `Test Extension Loading` step (`grep -q "ORA-" || echo "Extension loaded..."`) with a strict load verification query (`SELECT installed, loaded FROM duckdb_extensions() WHERE extension_name = 'oracle';`) and `./build/release/test/unittest "test/unit_tests/*"`.
   - Pass `ref: ${{ needs.validate-version.outputs.version }}` to `actions/checkout@v4` in `build-extension`, `deploy-gh-pages`, and `create-release`, and verify in `validate-version` that `description.yml`'s `version:` matches `VERSION#v`.
   - Move all `${{ ... }}` expressions out of `run:` blocks into `env:` and quote `"$GITHUB_OUTPUT"`.
   - Upgrade `peaceiris/actions-gh-pages@v3` to `@v4` and `softprops/action-gh-release@v1` to `@v2`.
   - Guard the Windows `link.exe` rename (`if (Test-Path "C:\Program Files\Git\usr\bin\link.exe") { ... }`) and use `ilammy/msvc-dev-cmd@v1` instead of hardcoding the VS 2022 Enterprise path.
2. In `integration-tests.yml`:
   - Remove the hardcoded job-level `ORACLE_HOME: /opt/oracle/instantclient_23_6` and `LD_LIBRARY_PATH: /opt/oracle/instantclient_23_6` (relying on `scripts/setup_oci_linux.sh`'s `$GITHUB_ENV` export for `instantclient_23_26`).
   - Remove the redundant `Build Extension` (`make release`) step before `Run Integration Tests` (`make integration`, which already depends on `release` and runs `test-unit`).
   - Add `permissions: contents: read`.
3. In `main-distribution-pipeline.yml`:
   - Add top-level `permissions: contents: read`.
