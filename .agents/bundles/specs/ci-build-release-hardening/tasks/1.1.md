# Task 1.1: Fix duckdb-update-check.yml daily PR churn, script injection, and auto-tag.yml exact tag check

## Objective

Remediate findings `H-24` (`duckdb-update-check.yml` part) and `M-23` (`duckdb-update-check.yml` and `auto-tag.yml` parts) in `.github/workflows/duckdb-update-check.yml` and `.github/workflows/auto-tag.yml`:
1. In `duckdb-update-check.yml`:
   - Check whether an open PR with head branch `feat/duckdb-v${NEW_VERSION}` already exists; if so, skip closing stale PRs, skip force-pushing, and exit cleanly without recreating the PR.
   - In `Close Stale PRs`, filter out `headRefName == "feat/duckdb-v${NEW_VERSION}"` so only genuinely superseded PRs are closed.
   - Pass `INPUT_CHECK_PRERELEASE: ${{ inputs.check_prerelease }}` and `NEW_VERSION: ${{ steps.check.outputs.new_version }}` / `CURRENT_VERSION: ${{ steps.check.outputs.current_version }}` via `env:` blocks, and quote `<<'PYTHON_SCRIPT'` and `"$GITHUB_OUTPUT"`.
   - Remove unused `pip install pyyaml` (kept `packaging`).
   - Change commit message prefix from `feat: Upgrade DuckDB to v${NEW_VERSION}` to `chore(deps): upgrade DuckDB to v${NEW_VERSION}` to comply with repository conventional commit standards.
2. In `auto-tag.yml`:
   - Replace `git ls-remote --tags origin | grep -q "$TAG_NAME"` with `git ls-remote --exit-code --tags origin "refs/tags/${TAG_NAME}" >/dev/null 2>&1` and quote `"$GITHUB_OUTPUT"`.

## Steps

### Step 1: Update `.github/workflows/duckdb-update-check.yml`

- In `Check for Updates`:
  - Add `env: INPUT_CHECK_PRERELEASE: ${{ inputs.check_prerelease }}` and read `os.environ.get('INPUT_CHECK_PRERELEASE', 'false').lower() == 'true'` inside a single-quoted `<<'PYTHON_SCRIPT'` heredoc.
  - Also check `gh pr list --head "feat/duckdb-v${NEW_VERSION}" --state open --json number --jq 'length'`; if `> 0`, set `update_available=false` and log that an open PR for `v${NEW_VERSION}` already exists.
- In `Close Stale PRs`:
  - Pass `NEW_VERSION: ${{ steps.check.outputs.new_version }}` in `env:` and filter `jq -r --arg branch "feat/duckdb-v${NEW_VERSION}" '.[] | select(.headRefName != $branch) | .number'`.
- In `Commit and Push` and `Create Pull Request`:
  - Pass `NEW_VERSION` and `CURRENT_VERSION` via `env:` instead of inline `${{ ... }}` in `run:`.
  - Use commit message `chore(deps): upgrade DuckDB to v${NEW_VERSION}`.

### Step 2: Update `.github/workflows/auto-tag.yml`

- In `Extract Version and Check Tag` (`.github/workflows/auto-tag.yml:37-48`):
  ```bash
  if git ls-remote --exit-code --tags origin "refs/tags/${TAG_NAME}" >/dev/null 2>&1; then
    echo "Tag $TAG_NAME already exists on remote."
    echo "tag_exists=true" >> "$GITHUB_OUTPUT"
  else
    echo "Tag $TAG_NAME does not exist. Proceeding with release."
    echo "tag_exists=false" >> "$GITHUB_OUTPUT"
  fi
  ```
