# Task 1.3: Harden Release Packaging, GitHub Pages Deployment, and Windows/Local Installation Documentation

## Objective
Resolve all root causes of GitHub Issues #20 and #22:
1. **Local Installation (`INSTALL '/path/to/oracle.duckdb_extension'; LOAD oracle;`)**:
   - DuckDB's `FileSystem::ExtractBaseName` extracts the extension name from the filename stem before the first `.` (`duckdb/src/common/file_system.cpp:313-320`) and resolves the C++ entrypoint `<stem>_duckdb_cpp_init` (`duckdb/src/main/extension/extension_load.cpp:507`). Installing a file named `oracle-windows_amd64.duckdb_extension` registers the extension as `oracle-windows_amd64` and fails to find `oracle_windows_amd64_duckdb_cpp_init`.
   - Update `.github/workflows/release-unsigned.yml` to package each platform's binary inside `oracle-${DUCKDB_PLATFORM}.zip` (for Windows) and `oracle-${DUCKDB_PLATFORM}.tar.gz` (for Linux and macOS) containing `oracle.duckdb_extension` (with exact inner filename `oracle.duckdb_extension`), while keeping `oracle-${DUCKDB_PLATFORM}.duckdb_extension` for backwards compatibility and computing SHA-256 checksums for both the archive and raw binary.
   - Update `Run Smoke Tests` in `.github/workflows/release-unsigned.yml` to test `INSTALL 'build/release/extension/oracle/oracle.duckdb_extension'; LOAD oracle;` on all 4 matrix platforms (including Windows).
2. **Remote Custom Extension Repository (`https://cofin.github.io/duckdb-oracle` and `https://raw.githubusercontent.com/cofin/duckdb-oracle/gh-pages`)**:
   - In `.github/workflows/release-unsigned.yml`:
     - Ensure `deploy_content/.nojekyll` is created before publishing to `gh-pages` via `peaceiris/actions-gh-pages@v4`.
     - Document both `https://cofin.github.io/duckdb-oracle` and `https://raw.githubusercontent.com/cofin/duckdb-oracle/gh-pages` (which serves the `gh-pages` branch tree directly over HTTPS even when GitHub Pages is not enabled in repository settings) in `release-unsigned.yml` release notes, `README.md`, and `docs/SETUP.md`.
3. **Windows & Cross-Platform Setup Documentation (Issue #22)**:
   - Update `README.md` and `docs/SETUP.md` to clearly document:
     - Why `INSTALL oracle FROM community;` returns HTTP 404 (the extension links against Oracle Instant Client's proprietary OCI library `oci.dll` / `libclntsh` at build and runtime and is distributed via this repository's unsigned extension repository).
     - Prerequisite Oracle Instant Client Basic setup for Windows (`oci.dll` in `PATH`), Linux (`libclntsh.so` in `LD_LIBRARY_PATH` / `ldconfig`), and macOS (`libclntsh.dylib` in `DYLD_LIBRARY_PATH`).
     - Remote installation via `SET custom_extension_repository` and offline/local installation from GitHub Releases by extracting `oracle.duckdb_extension` from `oracle-<platform>.zip` / `oracle-<platform>.tar.gz` (or renaming `oracle-<platform>.duckdb_extension` to `oracle.duckdb_extension`).

- **In `Run Smoke Tests` (lines 200-216)**:
  Verify `INSTALL 'build/release/extension/oracle/oracle.duckdb_extension'; LOAD oracle;` works end-to-end on all platforms (Linux, macOS, and Windows), stripping `\r` from Windows `duckdb.exe` output:
  ```yaml
      - name: Run Smoke Tests
        shell: bash
        env:
          RUNNER_OS_NAME: ${{ runner.os }}
        run: |
          # Verify extension installs and loads cleanly via local INSTALL + LOAD
          EXT_STATUS=$(./build/release/duckdb -unsigned -csv -noheader -c "INSTALL 'build/release/extension/oracle/oracle.duckdb_extension'; LOAD oracle; SELECT installed, loaded FROM duckdb_extensions() WHERE extension_name = 'oracle';" | tr -d '\r')
          echo "Extension status: $EXT_STATUS"
          if [ "$EXT_STATUS" != "true,true" ]; then
            echo "::error::Failed to install/load oracle extension (status: $EXT_STATUS)"
            exit 1
          fi

          if [ "$RUNNER_OS_NAME" != "Windows" ]; then
            ./build/release/test/unittest "test/unit_tests/*"
          fi
  ```
- **In `Prepare Artifacts` (lines 245-257)**:
  Create `oracle-${DUCKDB_PLATFORM}.zip` on Windows and `oracle-${DUCKDB_PLATFORM}.tar.gz` on Linux/macOS containing `oracle.duckdb_extension` at the archive root, alongside `oracle-${DUCKDB_PLATFORM}.duckdb_extension`, and include both explicit filenames in `oracle-${DUCKDB_PLATFORM}.sha256`:
  ```yaml
          # Create release directory with both platform-named binary and archive containing oracle.duckdb_extension
          mkdir -p deploy/release
          cp "build/release/extension/oracle/oracle.duckdb_extension" "deploy/release/oracle-${DUCKDB_PLATFORM}.duckdb_extension"

          PYTHON_BIN=$(command -v python3 || command -v python)
          "$PYTHON_BIN" - "$DUCKDB_PLATFORM" <<'PYEOF'
          import sys
          import tarfile
          import zipfile

          platform = sys.argv[1]
          src = "build/release/extension/oracle/oracle.duckdb_extension"
          if platform.startswith("windows"):
              archive_path = f"deploy/release/oracle-{platform}.zip"
              with zipfile.ZipFile(archive_path, "w", compression=zipfile.ZIP_DEFLATED) as zf:
                  zf.write(src, arcname="oracle.duckdb_extension")
          else:
              archive_path = f"deploy/release/oracle-{platform}.tar.gz"
              with tarfile.open(archive_path, "w:gz") as tf:
                  tf.add(src, arcname="oracle.duckdb_extension")
          PYEOF

          if [[ "$DUCKDB_PLATFORM" == windows* ]]; then
            ARCHIVE_FILE="oracle-${DUCKDB_PLATFORM}.zip"
          else
            ARCHIVE_FILE="oracle-${DUCKDB_PLATFORM}.tar.gz"
          fi

          # Generate checksums for this platform's artifacts (use shasum on macOS, sha256sum elsewhere)
          cd deploy/release
          if command -v sha256sum &> /dev/null; then
            sha256sum "oracle-${DUCKDB_PLATFORM}.duckdb_extension" "$ARCHIVE_FILE" > "oracle-${DUCKDB_PLATFORM}.sha256"
          else
            shasum -a 256 "oracle-${DUCKDB_PLATFORM}.duckdb_extension" "$ARCHIVE_FILE" > "oracle-${DUCKDB_PLATFORM}.sha256"
          fi
  ```
