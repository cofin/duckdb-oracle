# Task 1.2: Add Catalog Introspection Unit and Integration Tests (`duckdb_databases`, `duckdb_schemas`, `duckdb_tables`, `duckdb_columns`, `information_schema`, `SHOW TABLES`)

## Objective
Add comprehensive regression tests for GitHub Issue #21 across both `test/unit_tests/oracle/test_metadata.test` and `test/integration_tests/oracle/metadata.test`.

## Exact File Changes

### 1. `test/unit_tests/oracle/test_metadata.test`
- Add unit tests verifying that `FROM duckdb_databases()`, `FROM duckdb_schemas()`, `FROM duckdb_tables()`, `FROM duckdb_columns()`, `FROM information_schema.schemata`, `FROM information_schema.tables`, and `FROM information_schema.columns` execute cleanly with the `oracle` extension loaded.

### 2. `test/integration_tests/oracle/metadata.test`
- Before `ATTACH '' AS ora_lazy (TYPE oracle, SECRET oracle_meta_test);` (at `test/integration_tests/oracle/metadata.test:78-82`), reset `SET oracle_metadata_result_limit = 10000;` so the earlier `SET oracle_metadata_result_limit = 5;` on line 14 does not truncate `ZZZ_READ_LIMIT_TARGET` during schema/table scans.
- Add integration test cases against the live attached Oracle catalog verifying:
  1. `SELECT database_name, type, internal, readonly FROM duckdb_databases() WHERE database_name = 'ora_lazy'` returns `ora_lazy | oracle | false | false`, and `SELECT path FROM duckdb_databases() WHERE database_name = 'ora_lazy'` redacts the password (`***`).
  2. `SELECT COUNT(*) > 0 FROM duckdb_schemas WHERE database_name = 'ora_lazy'` (using the `duckdb_schemas` view, which filters `WHERE NOT internal`, not just the `duckdb_schemas()` table function) returns `true`, and `internal` is `false`.
  3. `SELECT COUNT(*) > 0 FROM duckdb_tables WHERE database_name = 'ora_lazy' AND table_name = 'ZZZ_READ_LIMIT_TARGET'` and `SELECT COUNT(*) > 0 FROM information_schema.tables WHERE table_catalog = 'ora_lazy' AND table_name = 'ZZZ_READ_LIMIT_TARGET'` return `true`.
  4. `SELECT column_name, data_type, is_nullable FROM duckdb_columns WHERE database_name = 'ora_lazy' AND table_name = 'ZZZ_READ_LIMIT_TARGET'` returns `ID | DOUBLE | true`.
  5. **Non-table synonym & unsupported column type resilience during schema scan**:
     - Create a sequence (`CREATE SEQUENCE meta_test_seq`), a synonym pointing to the sequence (`CREATE SYNONYM syn_meta_test_seq FOR meta_test_seq`), and a table with an unsupported column type (`CREATE TABLE meta_unsupported_long_tbl (id NUMBER NOT NULL, payload LONG)`).
     - Call `SELECT oracle_clear_cache();` so the new objects are visible to `ListObjects`, and verify `SELECT COUNT(*) > 0 FROM duckdb_tables() WHERE database_name = 'ora_lazy'` and `SELECT COUNT(*) > 0 FROM duckdb_columns() WHERE database_name = 'ora_lazy'` succeed without throwing `InternalException` or `NotImplementedException` (skipping `SYN_META_TEST_SEQ` and `META_UNSUPPORTED_LONG_TBL`).
     - Verify that directly querying `SELECT * FROM ora_lazy.meta_unsupported_long_tbl` still throws `NotImplementedException` (`Unsupported Oracle type "LONG"`).
  6. **Dynamic DDL / `oracle_clear_cache()` invalidation & `NOT NULL` column constraints**:
     - While `ora_lazy` remains attached (after `duckdb_tables()` has already enumerated its schema), create a new table via `oracle_execute(oracle_test_conn(), 'CREATE TABLE meta_dynamic_ddl_tbl (id NUMBER(10,0) NOT NULL, label VARCHAR2(20))')` and verify `SELECT COUNT(*) FROM duckdb_tables() WHERE database_name = 'ora_lazy' AND table_name = 'META_DYNAMIC_DDL_TBL'` immediately returns `1` without detaching/re-attaching.
     - Verify `SELECT column_name, is_nullable FROM duckdb_columns WHERE database_name = 'ora_lazy' AND table_name = 'META_DYNAMIC_DDL_TBL' ORDER BY column_index` returns `ID | false` and `LABEL | true`.
     - Clean up `meta_dynamic_ddl_tbl`, `meta_unsupported_long_tbl`, `syn_meta_test_seq`, and `meta_test_seq`.
