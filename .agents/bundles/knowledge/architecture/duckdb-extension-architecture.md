# DuckDB Extension Architecture & Subsystems

<!-- truth: start -->
- `src/oracle_extension.cpp` uses `DUCKDB_CPP_EXTENSION_ENTRY(oracle, loader)` and `extension_config.cmake` invokes both `duckdb_extension_load(oracle)` and `duckdb_extension_statically_link(oracle)`[^ext-entry].
- `OracleAttach` (`src/storage/oracle_storage_extension.cpp`) allocates a dedicated `make_shared_ptr<OracleCatalogState>` per `ATTACH` so concurrent attachments remain isolated[^storage-ext].
- `OracleCatalog` and `OracleSchemaEntry` (`src/storage/oracle_schema_entry.cpp`) inherit directly from `duckdb::Catalog` and `duckdb::SchemaCatalogEntry` (`info.internal = false`, never `DuckCatalog`) and synchronize cached entries via `OracleCatalogState::cache_generation`[^catalog-state][^schema-entry].
- `OracleTableEntry::LoadColumns` (`src/storage/oracle_table_entry.cpp`) loads column types, `NotNullConstraint`, and `ALL_TABLES.NUM_ROWS` (`estimated_row_count`) in a single round-trip and wires `TableFunction` optimizer callbacks (`get_bind_info`, `get_table_entry`, `cardinality`, `to_string`, `filter_prune`)[^table-entry].

DuckDB extensions dynamically extend the core database engine with custom storage backends, table functions, scalar functions, type systems, and authentication mechanisms without modifying upstream DuckDB binaries[^ext-entry].

```
+-----------------------------------------------------------------------------------+
| DuckDB Core Engine (v2.0.0)                                                        |
+-----------------------------------------------------------------------------------+
       |                                       |
       v (Load & Initialize)                   v (Resolve Credentials)
+-------------------------------+      +--------------------------------------------+
| Extension Entry Point         |      | SecretManager (`TYPE oracle`)              |
| - DUCKDB_CPP_EXTENSION_ENTRY  |      | - Key: secret name / scope                 |
|   (oracle, loader)            |      | - Fields: user, password, host, port, etc. |
+-------------------------------+      +--------------------------------------------+
       |
       +---------------------------------------+
       |                                       |
       v                                       v
+-------------------------------+      +--------------------------------------------+
| StorageExtension Hook         |      | Table & Scalar Functions                   |

|           +---> OracleTable   |

+-------------------------------+
```

## 1. Extension Loading Lifecycle & Static/Loadable Build Registration

When DuckDB runs `LOAD oracle;`, the runtime invokes the C++ extension entrypoint generated by `DUCKDB_CPP_EXTENSION_ENTRY` (`src/oracle_extension.cpp`)[^ext-entry]:

```cpp
DUCKDB_CPP_EXTENSION_ENTRY(oracle, loader) {
    duckdb::LoadInternal(loader);
}
```

- **Version Lockstep**: `DUCKDB_CPP_EXTENSION_ENTRY` exports `oracle_duckdb_cpp_init(ExtensionLoader &)` and `oracle_version()` returning the DuckDB C API version compiled into the extension.
- **`LoadInternal(ExtensionLoader &loader)`**: Registers functions (`loader.RegisterFunction(...)`), settings (`config.AddExtensionOption(...)`), secrets (`RegisterOracleSecret(loader)`), and storage hooks (`config.storage_extensions["oracle"]`)[^ext-entry].
- **Dual CMake Registration (`extension_config.cmake`)**: In DuckDB `v2.0.0`, `extension_config.cmake` calls both `duckdb_extension_load(oracle)` and `duckdb_extension_statically_link(oracle)` so static targets (`unittest`, `duckdb` shell) link `oracle_extension` and receive `-DEXT_VERSION_ORACLE="..."`.
- **Zero-SDK Load Contract (`CMakeLists.txt`)**: Neither `oracle_extension` nor `oracle_loadable_extension` links against `libclntsh` at build time (only `${CMAKE_DL_LIBS}`). This allows `FORCE INSTALL oracle; LOAD oracle;` in `duckdb/community-extensions` documentation and verification jobs to succeed on clean runners without Oracle Instant Client installed.

## 2. Storage Extension Interface (`StorageExtension`)

DuckDB allows custom engines to act as attached databases via `ATTACH '' AS ora (TYPE oracle, ...)`[^storage-ext]:

```cpp
auto &config = DBConfig::GetConfig(db);
auto storage_extension = make_uniq<OracleStorageExtension>();
config.storage_extensions["oracle"] = std::move(storage_extension);
```

- **`OracleAttach` (`src/storage/oracle_storage_extension.cpp`)**: Allocates a dedicated `make_shared_ptr<OracleCatalogState>(connection_string, wallet_path)` for every `ATTACH` invocation, applies per-attachment options via `state->ApplyOptions(info.options)`, registers the state under the attached database alias (`OracleCatalogState::Register(state, name)`), and returns `CreateOracleCatalog(&db, state)`[^storage-ext].
- **`OracleCreateTransactionManager`**: Looks up the per-catalog state via `OracleCatalogState::LookupByAlias(db.GetName())` and constructs `OracleTransactionManager(db, state)` with a mutex-guarded active transaction map.

## 3. Catalog & Schema Hierarchy (Per-ATTACH State Isolation)

DuckDB organizes attached databases into a tree of catalog objects with strict per-`ATTACH` catalog state isolation:

1. **`OracleCatalogState` (`src/storage/oracle_catalog.cpp`)**[^catalog-state]:
   - Encapsulates metadata discovery queries (`ALL_USERS`, `ALL_OBJECTS`, `ALL_SYNONYMS`, `ALL_TAB_COLUMNS`, `ALL_VEC_COLUMNS`, `ALL_PART_TABLES`, `ALL_TAB_PARTITIONS`) using parameterized bind variables (`ExecuteMetadataQueryWithStringBinds`), lazy schema discovery (`oracle_lazy_schema_loading`), `CURRENT_SCHEMA` resolution, and per-catalog metadata caches.
   - Maintains an atomic `cache_generation` counter incremented by `ClearCaches()` so `OracleCatalog` and `OracleSchemaEntry` synchronize their in-memory entry caches in $O(1)$ time while moving evicted entries to `retired_schemas` / `retired_tables` to preserve pointer stability for in-flight queries.
   - Filters `SYNONYM` rows in `ListObjects` so only local (`db_link IS NULL`) synonyms targeting `TABLE`, `VIEW`, or `MATERIALIZED VIEW` objects in `ALL_OBJECTS` are enumerated.
   - Acquires a short-lived `OracleConnection` inside `ExecuteMetadataQuery` / `ExecuteMetadataQueryWithStringBinds` that immediately returns its pooled handle to `OracleConnectionManager` after each metadata query, preventing self-deadlock when `oracle_connection_limit = 1`.
   - Records per-`ATTACH` options in `settings.attach_overridden_keys` so `GetOracleSettings` preserves `ATTACH`-level overrides unless a session explicitly sets a `SettingScope::LOCAL` override.

2. **`OracleCatalog` & `OracleSchemaEntry` (`src/storage/oracle_schema_entry.cpp`)**[^schema-entry]:
   - `OracleCatalog` subclasses `duckdb::Catalog` directly (never `DuckCatalog`), overriding `LookupSchema`, `ScanSchemas`, `GetDefaultSchema`, `InMemory()`, `GetDBPath()` (redacting passwords via `RedactOracleConnectionString`), `GetDatabaseSize()`, and `PlanInsert` (passing resolved `oracle_table.GetSchemaName()` and `oracle_table.GetTableName()` to `PhysicalOracleInsert` for cross-schema and synonym-backed targets).
   - `OracleSchemaEntry` subclasses `duckdb::SchemaCatalogEntry` directly with `info.internal = false` (so DuckDB system views `duckdb_schemas`, `duckdb_tables`, `duckdb_columns`, and `information_schema.*` include attached Oracle schemas and tables), overriding `LookupEntry`, `GetSimilarEntry` (scoring against `ListObjects` without triggering $N$ `all_tab_columns` queries), and `Scan` (skipping tables with unsupported column types via `unresolvable_entries` while keeping direct `LookupEntry` strict), and throwing clean `BinderException` diagnostics for unsupported DDL operations.

3. **`OracleTableEntry` (`src/storage/oracle_table_entry.cpp`)**[^table-entry]:
   - Subclasses `duckdb::TableCatalogEntry`, loading column metadata, `NotNullConstraint` (`NULLABLE = 'N'`), and `ALL_TABLES.NUM_ROWS` (`estimated_row_count`) in a single round-trip via `LEFT JOIN all_tables` on `ALL_TAB_COLUMNS` (and enriching Oracle 23ai `VECTOR` columns from `ALL_VEC_COLUMNS` and spatial SRIDs from `ALL_SDO_GEOM_METADATA`).
   - Overrides `GetScanFunction` to construct an `OracleBindData` with full column metadata, `original_types`, `estimated_row_count`, `table_entry = this`, and DuckDB 2.0 `TableFunction` optimizer callbacks (`get_bind_info = OracleGetBindInfo`, `get_table_entry = OracleGetTableEntry`, `cardinality = OracleCardinality`, `to_string = OracleToString`).

## 4. SecretManager Integration (`src/oracle_secret.cpp`)

DuckDB includes a unified `SecretManager` for persistent and temporary credential storage[^secret-mgr]. The extension registers an `oracle` secret type:

```sql
CREATE SECRET my_oracle (
    TYPE oracle,
    USER 'scott',
    PASSWORD 'tiger',
    HOST 'localhost',
    PORT 1521,
    SERVICE 'FREEPDB1'
);
ATTACH '' AS ora (TYPE oracle, SECRET my_oracle);
```

The extension resolves secrets during `ATTACH` or table function invocation via `ResolveOracleConnection` (`src/oracle_connection_resolver.cpp`), automatically parsing wallet paths, credentials, and host descriptors.
